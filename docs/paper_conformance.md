| 6.1 GPT-4o를 평가기로도 사용 | 자동 평가를 범위에서 제외(개정 4) | **범위 밖** |

### 모델을 붙이며 발견한 것

**GPT-5.6 계열은 `temperature=0`을 받지 않습니다.** 기본값(1)만 허용합니다.

```text
BadRequestError: Unsupported value: 'temperature' does not support 0 with this model.
```

그래서 `sampling_args()`로 모델별 분기를 두었습니다. GPT-4o만 `temperature=0`을 쓰고, GPT-5.6 계열은 기본값으로 돕니다. **같은 질문이라도 Luna·Terra는 실행할 때마다 답이 달라질 수 있습니다.** 논문은 이 점을 언급하지 않았습니다.

## 7.2 파이프라인별 심층 분석 (논문의 세 가지 발견)

논문의 발견이 우리 구현에서도 관찰되는지 봅니다. 아래는 같은 질문("택배가 파손돼서 왔어요")을 세 모델로 돌린 실측입니다. **표본 1건이므로 경향 확인 수준입니다.**

| 모델 | Vanilla | Native | Agentic | 비고 |
|---|---|---|---|---|
| GPT-5.6 Luna | 11.1초 / $0.00140 | 8.7초 / $0.00217 | 39.4초 / $0.00820 · **폴백** | Critic 3회 미달 |
| GPT-5.6 Terra | 25.5초 / $0.02195 | 6.2초 / $0.01675 | 16.7초 / $0.02766 · 정상 | |
| GPT-4o | 3.5초 / $0.00405 | 4.5초 / $0.01987 | 9.3초 / $0.02637 · 정상 | |

| 논문의 발견 | 구현에서 확인 가능한가 | 현재 상태 |
|---|---|---|
| 1. 인지 부하 역설 (GPT-4o가 Agentic에서 오히려 나빠짐) | **품질 점수를 측정하지 않으므로 직접 확인 불가.** 다만 GPT-4o Agentic은 폴백 없이 완주 | 판정 보류 |
| 2. 맥락 혼동 (Native RAG에서 성능 급락) | 같음. 품질 측정이 없어 확인 불가 | 판정 보류 |
| 3. 아키텍처 시너지 (Luna·Terra + Agentic) | 같음 | 판정 보류 |
| 토큰 42% 절감 (Agentic < Native) | **재현되지 않음.** Agentic이 Native보다 토큰을 2~4배 더 씀 | **불일치** (아래 §쟁점 3) |
| Luna 결합 시 GPT-4o 대비 약 90% 비용 절감 | **재현됨.** Agentic 기준 $0.02637(4o) → $0.00820(Luna) = **69% 절감**. 단가만 보면 92% | 부분 일치 |
| Intent Router가 무관한 질의를 선제 차단 | 재현됨 ("서울 맛집" → 즉시 거절, 토큰 최소) | **일치** |

## 쟁점과 해석

### 쟁점 1. 지연 시간이 논문 기준(10~15초)을 넘는다

Agentic이 Luna에서 39초, Terra에서 17초입니다. 원인은 두 가지입니다.

1. **Critic 재시도**: 3회까지 돌면 생성·검증이 6번 실행됩니다. 논문도 9.2절에서 '과잉 검열' 문제를 인정했습니다.
2. **GPT-5.6의 추론 시간**: Luna는 Vanilla 단독 호출도 11초가 걸립니다. 논문이 가정한 지연 예산은 GPT-4o 기준으로 보입니다.

대응은 IMP-02(Critic 동적 임계치)입니다. 지금은 논문 방식 그대로 둡니다.

### 쟁점 2. 청킹이 논문과 다르다

논문 4.3절은 `chunk size=500, overlap=100`을 씁니다. 그대로 하면 별표의 표가 뭉개져서 경로(`별표Ⅱ > 품목 > 분쟁유형`)라는 개념 자체가 생기지 않습니다. 이전 구현(Notion 기록)이 그 방식이었고, 검색 결과가 개정 이력·부칙 덩어리였습니다.

그래서 **문서 구조를 복원해 행 단위로 자르는 방식**으로 바꿨습니다. 논문의 목적(정확한 조항 검색)은 지키되 수단을 바꾼 경우입니다.

### 쟁점 3. 토큰 42% 절감이 재현되지 않는다

논문은 Agentic이 Native보다 토큰을 42% 적게 쓴다고 합니다(부록 B: Native 10,091 → Agentic 5,873). 우리 구현은 반대입니다.

| | 논문 | 우리 구현 (Luna) |
|---|---|---|
| Native | 10,091 토큰 | 3,167 토큰 |
| Agentic | 5,873 토큰 | 12,904 토큰 |

이유는 분명합니다.

- **논문의 Native는 문서를 정제 없이 전량 주입**합니다(부록 D 4-B). 그래서 1만 토큰이 넘습니다. 우리 Native는 리랭킹으로 상위 5개만 넣어 3천 토큰입니다.
- **우리 Agentic은 Critic 재시도로 생성이 여러 번** 돕니다. 논문의 42% 절감은 '라우터가 무관한 질의를 걸러서' 생긴 절감이고, 이는 **도메인 밖 질문이 섞인 100건 평균**에서 나온 수치입니다. 단건 정책 질의만 보면 Agentic이 더 쓰는 게 맞습니다.

즉 논문 수치와 비교하려면 **도메인 밖 질문을 포함한 다수 질의의 평균**을 봐야 합니다. 대시보드가 그 평균을 보여주므로, 질의가 쌓이면 다시 판정할 수 있습니다.

## 정리

| 구분 | 건수 |
|---|---|
| 일치 | 10 |
| 일치(변형) — 목적은 지키고 수단이 다름 | 3 |
| 불일치 | 3 (지연 시간, 4o-mini 역할 분리 제외, 토큰 절감) |
| 범위 밖 — 논문이 스스로 제외했거나 이번 제품 범위 밖 | 4 |
| 판정 보류 — 품질 점수를 측정하지 않아 확인 불가 | 3 |

**구조는 논문을 따릅니다.** 라우터 → 메모리 → 하이브리드 검색 → RRF → 리랭킹 → 생성 → Critic → 재시도/폴백의 흐름과 각 노드의 스키마가 논문 서술과 맞습니다.

**다른 점 세 가지는 모두 이유가 분명합니다.** 청킹은 논문 방식으로는 표가 깨져서, 모델 역할 분리는 사용자 지시로, 토큰 절감은 비교 조건(Native가 전량 주입인지)이 달라서입니다.

**7.2절의 세 발견은 아직 판정할 수 없습니다.** 품질 점수(L2)를 측정해야 하는데 자동 평가를 범위에서 뺐기 때문입니다. 오프라인 평가(IMP-08)를 붙이면 판정할 수 있습니다.
