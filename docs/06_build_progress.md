### 품목 매칭을 위해 추가한 것 (논문에 없는 부분)

별표Ⅱ는 품목이 달라도 문구가 거의 같아서(`ㅇ 계약취소` 수준) 벡터 검색만으로는 품목이 구분되지 않았다. 그래서 두 가지를 더했다.

1. **질의 확장**: 별표Ⅰ(대상품목) 매핑 + `config/synonyms.yaml`(일상어 → 고시 용어). 예: 노트북 → 퍼스널컴퓨터·전자제품·사무용기기
2. **품목 한정 검색**: 질문에서 품목이 특정되면 그 품목 표 안에서 한 번 더 검색해 RRF에 한 축으로 얹음 (임베딩 재사용이라 추가 비용 없음)

## 구축 중 고친 것

파싱 단계에서 자동 검증이 실제 데이터 손실을 여러 번 잡았다.

1. 한 쪽에 표가 여러 개일 때 제목이 뒤섞이던 문제 → 표마다 제목을 따로 찾음
2. 분쟁유형이 두 줄일 때 둘째 줄이 버려지던 문제
3. 줄 끝 숫자가 표 테두리를 넘어가 잘리던 문제
4. 품목 제목이 표 안 첫 줄에 있는 경우를 놓쳐 표가 쪼개지던 문제 (전자제품 표가 p14/p15로 갈라져 있었음)
5. 청크 ID 중복 (같은 조문 번호가 두 번 실린 경우)

검증 규칙도 손봤다.

- 해결기준 마커 개수 불일치는 **경고**로 (한 행에 해결기준이 둘 이상 붙는 표가 실제로 있음)
- 숫자 비교는 단위를 떼고 숫자만 (`24`와 `24시간`이 줄바꿈 때문에 다르게 잡히던 문제)

그 밖에 고친 것:

- **Critic 재시도 횟수가 세어지지 않아 5회까지 돌던 버그** → 검증 횟수를 따로 세도록 수정
- **그래프가 옛 청크 ID를 가리키던 문제** → 현재 청크에 없는 ID는 버리고 다시 추출
- 임베딩을 **증분 갱신**으로 (파싱을 고칠 때마다 전체 비용을 내지 않도록)
- 로그 저장을 DB 종류에 기대지 않게 (`merge` 사용) → 로컬은 SQLite, 운영은 Neon
