## 3-1. 정보 구조

### 화면 목록과 접근 권한

| 경로 | 화면 | 접근 | 업무 흐름 |
|---|---|---|---|
| `/` | 소개 | 공개 | — |
| `/chat` | 챗봇 | 공개 | W2, W3 |
| `/dashboard` | 대시보드 | 공개 | W4 |
| `/admin` | 관리자 로그인 | **숨김 주소**, 메뉴에 없음 [결정] | W5 |
| `/admin/logs` | 로그 목록 | 관리자 | W5 |
| `/admin/logs/:requestId` | 로그 상세 | 관리자 | W5 |
| (설정 패널) | API 키 입력·변경·삭제 | 공개 | W2, W3 |

### 내비게이션

```text
[공통 상단 바]  로고 · 소개 · 챗봇 · 대시보드 · ⚙ API 키        ※ 모바일: 로고 · ☰ · ⚙
     │
     ├─ /            소개 ──[시작하기]──▶ /chat                         [결정] 첫 화면은 소개
     ├─ /chat        [전체 파이프라인 보기 | Vanilla | RAG | Agentic]   [결정] 상단 탭으로 모드 전환
     ├─ /dashboard
     └─ ⚙            API 키 패널 (입력 / 변경 / 삭제)                  [결정] 인라인 안내 + 설정

[관리자, 숨김]  /admin ──로그인──▶ /admin/logs ──행 클릭──▶ /admin/logs/:requestId
                관리자 화면 상단 바: 로그 · 로그아웃
```

| 규칙 | 내용 |
|---|---|
| 소개 페이지 | 매번 `/`로 들어오면 소개가 보임. 다시 온 사용자는 메뉴의 '챗봇'으로 바로 이동 [기본값] |
| 모바일 메뉴 | 상단 햄버거 메뉴 [기본값] |
| 관리자 미로그인 | `/admin/logs` 계열에 접근하면 `/admin`으로 보냄 |

## 3-2. 화면별 핵심 목표

| 화면 | 핵심 목표 | 가장 먼저 보여야 할 것 |
|---|---|---|
| 소개 | 3개 파이프라인이 무엇이 다른지 이해하고 시작하게 함 | 파이프라인 차이 그림, [시작하기] |
| 챗봇 · 단일 모드 | 일반 챗봇처럼 질문하고 답을 받음 | 답변 |
| 챗봇 · 전체 보기 | 같은 질문에 대한 3개 답의 차이를 한눈에 봄 | 3개 답변이 나란히, 끝나는 순서대로 |
| 대시보드 | 파이프라인별 비용·속도·경로 차이를 수치로 봄 | 파이프라인별 요약 카드 |
| 로그 목록 | 원하는 요청을 빠르게 찾음 | 질문 원문, 모드, 결과, 시각 |
| 로그 상세 | 왜 그렇게 답했는지 추적함 | 3개 답변 비교 + 노드별 처리 과정 + 검색 근거 원문 |

### 소개 (`/`)

| 영역 | 내용 |
|---|---|
| 파이프라인 차이 그림 [결정] | Vanilla(LLM만) / Native RAG(검색 → 생성) / Agentic RAG(라우터 → 하이브리드 검색 → 생성 → Critic 검증 → 재시도·폴백). 논문 출처 표기 |
| 사용 방법과 비용 안내 [결정] | OpenAI API 키가 필요함. 요청 비용은 본인 키로 청구됨. 키는 이 브라우저에만 저장되고 서버에는 저장되지 않음. 모든 노드에 `gpt-4o-mini` 사용 |
| 지식베이스 출처 [결정] | 소비자분쟁해결기준(공정거래위원회고시 제2025-14호, 2025.12.18 시행), 전자상거래법(법률 제21312호, 2026.7.21 시행) |
| [시작하기] | `/chat`으로 이동 |

### 챗봇 (`/chat`)

| 요소 | 단일 모드 (Vanilla / RAG / Agentic) | 전체 파이프라인 보기 |
|---|---|---|
| 배치 | 일반 채팅 (질문 → 답변이 아래로 쌓임) | **데스크톱 3열, 모바일은 Vanilla / RAG / Agentic 탭** [결정]. 모바일 탭에 진행·완료 표시 |
| 처리 과정 | **접힘**, '처리 과정 보기'로 펼침 [결정] | **펼침** [결정] |
| 답변 수치 | 답변 아래에 작게 `4.2초 · 1,240 토큰 · $0.0004` [결정] | 칸마다 같은 형식 [결정] |
| 대화 기록 | **탭마다 따로 유지**, 새로고침하면 모두 사라짐 [결정] | 같음 |
| 예시 질문 | 빈 화면에 **예시 질문 칩** 3~4개. 누르면 입력창에 채워짐 [결정] | 같음 |
| 모드 설명 | 탭 옆 도움말(ⓘ)에 한 줄 설명 [기본값] | 같음 |

**예시 질문 칩** [기본값, 문구는 5차에서 확정]: CSV가 아닌 직접 쓴 문장으로 만듭니다. 파이프라인 차이가 잘 드러나도록 구성합니다.
- 청약철회: "인터넷으로 산 옷, 태그 뗐는데 환불되나요?"
- 품목별 해결기준: "산 지 한 달 된 노트북이 고장 났어요. 교환되나요?"
- 계약 해지: "헬스장 계약 중도 해지하면 위약금이 얼마인가요?"
- 도메인 밖: "서울 맛집 추천해줘" (Agentic의 거절을 확인하는 용도)

**답변 카드의 처리 과정** (파이프라인별로 있는 것만 표시)

| 항목 | Vanilla | Native RAG | Agentic RAG |
|---|---|---|---|
| 라우터 판정 (경로 + 이유) | — | — | ○ |
| 분쟁 대상 (상품명, 분쟁 유형) | — | — | ○ |
| 검색 근거 (상위 5개: 경로, 발췌, 출처 벡터/그래프) | — | ○ | ○ (회차별) |
| Critic 판정 (회차별 3기준 + 피드백) | — | — | ○ |
| 폴백 사유 | — | — | 폴백 시 |

### 대시보드 (`/dashboard`) [기본값]

| 영역 | 내용 |
|---|---|
| 기간 필터 | 전체 / 최근 7일 / 최근 30일 |
| 요약 카드 3장 | 파이프라인별 요청 수, 지연 p50/p95, 평균 토큰, 평균 비용 |
| 노드별 소요 시간 | 노드별 평균 소요 시간 막대 (Agentic 중심) |

### 관리자 (`/admin`, `/admin/logs`, `/admin/logs/:requestId`)

| 화면 | 내용 |
|---|---|
| 로그인 | 아이디·비밀번호 입력 (`admin`/`admin`) |
| 로그 목록 [기본값] | 표 열: 시각, 질문 앞부분, 모드, 결과(파이프라인별 배지), 지연, 비용. 필터: 모드, 파이프라인, 결과, 기간, 질문 키워드. 최신순, 페이지 나눔 |
| 로그 상세 | 상단: 질문 원문, 모드, 시각, 브라우저 ID, 빌드 ID. 본문: 실행별 답변 카드(전체 보기 요청이면 3열 비교 [결정]). 실행마다 노드 타임라인(순서, 소요 시간, 토큰, 판정 결과)과 검색 결과 표(원문 스냅샷, 점수, 벡터/그래프, 리랭킹 순위, 선택 여부) |

## 3-3. 상태별 화면

### 챗봇: 입력 영역

| 상태 | 화면 |
|---|---|
| 서버 준비 중 | 화면에 들어오면 곧바로 서버를 깨움. 아직 깨어나지 않았으면 입력창 위에 **"서버를 깨우는 중"** 표시 (무료 호스팅이라 쉬면 잠듦) [결정, 4차] |
| 키 미입력 | 입력창 자리에 **키 입력 칸** + 발급 방법 링크 + "키는 이 브라우저에만 저장됩니다" |
| 키 확인 중 | 입력 칸 아래 스피너 |
| 키 무효 | "유효하지 않은 키입니다" + 다시 입력 |
| 대기 (키 유효) | 질문 입력창 + 전송 버튼. 대화가 없으면 예시 질문 칩 |
| 실행 중 | 전송 버튼이 **중지 버튼**으로 바뀜. **새 질문과 탭 전환 잠금** [결정]. 상단 메뉴로 다른 페이지에 가려 하면 "실행을 중지하고 이동할까요?" 확인 [기본값] |

### 챗봇: 답변 카드 (단일 모드의 답변, 전체 보기의 각 칸)

| 상태 | 화면 |
|---|---|
| 대기 | 카드 자리에 '대기 중' |
| 진행 중 | **로딩 표시만** [결정, 5차 검수에서 변경]. 단계 이름과 회차는 보여주지 않음. 처리 과정은 완료 후 트레이스에서 확인 |
| 답변 | 답변 본문 + 수치 + 처리 과정 |
| 거절 | 고정 거절 문구 + '도메인 밖' 배지 |
| 폴백 | 답변 + '폴백됨: Native RAG 결과' 배지 + 처리 과정에 폴백 사유 |
| 실패: 키 무효 | "API 키가 유효하지 않습니다" + [키 다시 입력] |
| 실패: 한도 초과 | "OpenAI 사용 한도를 초과했습니다" + OpenAI 결제 페이지 안내 |
| 실패: 시간 초과 | "60초 안에 답하지 못했습니다" + [다시 시도] |
| 실패: 기타 | "오류가 발생했습니다" + [다시 시도] |
| 취소 | '중지됨' + 그때까지 든 비용 |

**전체 보기 규칙**: 칸마다 위 상태를 따로 표시합니다. 끝난 칸부터 결과가 채워지고, 모바일 탭에는 칸 상태(진행 중 / 완료 / 실패)를 점으로 표시합니다. Agentic이 폴백되면 옆 칸의 Native 결과와 같은 답이 '폴백됨' 배지와 함께 나옵니다.

### 대시보드

| 상태 | 화면 |
|---|---|
| 로딩 | 카드·차트 자리에 스켈레톤 |
| 데이터 없음 | "아직 기록된 요청이 없습니다" + [챗봇으로 가기] |
| 표본 적음 | 해당 기간 요청이 파이프라인별 10건 미만이면 "표본이 적어 수치가 불안정할 수 있습니다" 표시 [기본값] |
| 오류 | "수치를 불러오지 못했습니다" + [다시 시도] |

### 관리자

| 화면 | 상태 | 화면 |
|---|---|---|
| 로그인 | 실패 | "아이디 또는 비밀번호가 올바르지 않습니다" |
| 로그 목록 | 결과 없음 | "조건에 맞는 로그가 없습니다" + [필터 초기화] |
| 로그 상세 | 실행 중인 요청 | 상태 배지 '진행 중'. 새로고침하면 갱신 |
| 공통 | 미로그인 접근 | `/admin`으로 이동 |
