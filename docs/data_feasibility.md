# 목업 화면 데이터의 실현 가능성 점검

- 작성일: 2026-09-20
- 목적: 5차 목업에 그려 둔 값(노드 타임라인, 비용, 검색 결과 표의 경로·벡터·그래프·사용)이 **실제로 수집 가능한지** 확인한다.
- 방법: 실제 원문(`ref/`)으로 파싱 프로토타입을 돌리고, 라이브러리 사양을 확인했다.

## 요약

| 목업의 값 | 판정 | 근거 |
|---|---|---|
| 노드 타임라인 (노드·회차·소요 시간) | **가능** | 우리가 LangGraph 노드를 직접 작성하므로 노드 진입·종료 시각을 기록하면 된다 |
| 노드별 토큰 | **가능** | langchain-openai 응답의 `AIMessage.usage_metadata`에 호출별 `input_tokens`/`output_tokens`가 들어온다 |
| 비용 | **가능(계산값)** | OpenAI는 비용을 돌려주지 않는다. 토큰 × 단가로 계산한다. `gpt-4o-mini` 기준 입력 $0.15 / 출력 $0.60 / **캐시된 입력 $0.075** per 1M |
| 검색 결과 '경로' | **가능** | 아래 §2에서 실제 원문으로 생성 확인 |
| 검색 결과 '벡터' 점수 | **가능** | ChromaDB가 거리(distance)를 주므로 유사도로 환산해 저장한다. 그래프로만 찾은 청크는 값이 없어 `-`로 표시 |
| 검색 결과 '그래프' | **가능** | 우리가 두 경로를 병합하므로 어느 경로에서 왔는지 기록하면 된다 |
| 검색 결과 '사용' | **가능(의미 주의)** | '리랭킹 상위 5건에 들어 **프롬프트에 실제로 들어갔다**'는 뜻. '답변이 이 문장을 인용했다'는 뜻이 아니다 |

## 1. 노드 기록·토큰·비용

### 노드로 요청이 넘어간 기록

LangGraph의 각 노드는 우리가 작성하는 파이썬 함수입니다. 노드 시작과 끝에서 시각을 찍고, 그 노드가 만든 결과(라우터 판정, 검색 쿼리, Critic 판정)를 상태에 담아 두면 그대로 로그가 됩니다. 재시도 회차도 상태에 들고 있는 값이라 함께 기록됩니다.

### 토큰

`ChatOpenAI` 호출 결과 메시지에 `usage_metadata`가 붙습니다.

```python
res = llm.invoke(messages)
res.usage_metadata
# {"input_tokens": 4200, "output_tokens": 460, "total_tokens": 4660,
#  "input_token_details": {"cache_read": 3584}}
```

노드마다 LLM을 한 번씩 부르므로 **노드별 토큰이 그대로 나옵니다.** 검색·리랭킹 병합처럼 LLM을 부르지 않는 단계는 토큰이 0입니다(목업과 같음).

주의할 점:
- 답변을 스트리밍하면 usage가 따로 오지 않습니다. 우리는 **답변을 확정한 뒤 한 번에 표시**하기로 했으므로 문제 없습니다.
- 임베딩 호출도 usage를 돌려주므로 질의 임베딩 토큰까지 합산할 수 있습니다.

### 비용

OpenAI 응답에는 금액이 없습니다. **토큰 × 설정 파일의 단가**로 계산합니다. 캐시된 입력은 단가가 다르므로(1/2) `cache_read`를 빼서 따로 계산해야 실제 청구액과 맞습니다.

```text
cost = (input_tokens - cache_read) × 0.15/1M + cache_read × 0.075/1M + output_tokens × 0.60/1M
```

4차 문서의 **단가 버전을 실행 레코드에 함께 저장**한다는 규칙이 여기서 의미를 갖습니다.

## 2. '경로'는 어떻게 저렇게 깔끔한가

### 걱정한 문제가 맞습니다

일반적인 `RecursiveCharacterTextSplitter`로 500자씩 자르면 조문 중간이 잘리고, 표는 열이 섞여서 "경로"라는 개념 자체가 생기지 않습니다. 이전 구현(Notion 기록)이 바로 그 방식이었고, 그래서 검색된 청크가 개정 이력·부칙 같은 덩어리였습니다.

### 그래서 스플리터를 쓰지 않습니다

지식베이스를 만들 때 **문서 구조를 먼저 복원하고, 그 단위를 청크로 삼습니다.** 경로는 파싱할 때 우리가 부여하는 메타데이터입니다. 실제 원문으로 확인한 결과는 다음과 같습니다.

**법령 (전자상거래법)**: 조문 57개 → **항 단위 청크 193개**

```text
전자상거래법 > 제17조(청약철회등) > 제1항   (474자)
전자상거래법 > 제17조(청약철회등) > 제2항   (517자)
전자상거래법 > 제17조(청약철회등) > 제3항   (139자)
```

청크 길이는 최소 37자, 중앙값 142자, 최대 1,264자입니다. 항이 없는 조문은 조 전체가 한 청크입니다.

**별표Ⅱ (품목별 해결기준)**: 3열 표 150개 → **행 청크 1,015개**

```text
별표Ⅱ > ⑥이동통신서비스업 > 3) 주생활지…통화품질 불량 > - 가입 14일 이내
  → ㅇ 계약해제
별표Ⅱ > ⑥이동통신서비스업 > 3) 주생활지…통화품질 불량 > - 가입 15일 이후 6개월 이내
  → ㅇ 위약금 및 할인반환금 없이 계약해지 및 해지신청 직전 1개월 기본료 50% 감면
```

150개 표 중 **행 복원에 실패한 표는 1개**였습니다. 이 1개가 LLM 보정(C안) 대상입니다.

### 다만 새로운 문제가 있습니다 (중요)

표에서 뽑은 해결기준 텍스트는 매우 짧습니다.

| 항목 | 값 |
|---|---|
| 해결기준 길이 중앙값 | **17자** (예: `ㅇ 계약취소`) |
| 30자 미만 비율 | **81%** |
| 최대 | 268자 |

`ㅇ 계약취소` 다섯 글자를 그대로 임베딩하면 품목이 다른 수십 개 행이 거의 같은 벡터가 됩니다. 검색이 망가집니다.

**해결책**: 임베딩에 넣는 텍스트와 화면에 보여주는 텍스트를 분리합니다.

```text
임베딩용 텍스트 = 경로 + 분쟁유형 + 해결기준 + 표의 비고
  "소비자분쟁해결기준 별표Ⅱ 이동통신서비스업. 주생활지에서의 통화품질 불량, 가입 15일 이후
   6개월 이내. 해결기준: 위약금 및 할인반환금 없이 계약해지 및 해지신청 직전 1개월 기본료
   50% 감면. 비고: 통화품질불량은 주생활지에서 엔지니어가 측정하여 확인함…"

메타데이터  = { path, 업종, 품목, 분쟁유형 경로, 해결기준 원문, 비고, 쪽 번호, 표 ID }
```

이렇게 하면 임베딩 텍스트 길이가 **중앙값 237자, 최대 1,008자**가 되어 검색이 제대로 동작하고, 화면에는 메타데이터의 `path`와 해결기준 원문만 깔끔하게 보여줄 수 있습니다.

### 예상 청크 수

| 문서 | 청크 |
|---|---|
| 전자상거래법 (항 단위) | 193 |
| 별표Ⅱ (행 단위) | 1,015 |
| 별표Ⅰ·Ⅲ·Ⅳ (행 단위, 추정) | 200~300 |
| **합계** | **약 1,400~1,500** |

4차에서 잡은 그래프 구축 비용(1달러 미만) 추정과 일치합니다.

## 3. '그래프'와 '사용' 열의 의미

두 값 모두 **검색 파이프라인이 스스로 남기는 기록**입니다. 외부에서 받아오는 값이 아닙니다.

```text
질문 ──┬─ 벡터 검색  → 청크 20건 (각각 유사도 점수)
       └─ 그래프 탐색 → 청크 9건  (유사도 점수 없음)
                 ↓
            RRF 병합 → 후보 29건        ← 여기서 각 청크에 '어디서 왔는지' 기록
                 ↓
         LLM 리랭킹 → 상위 5건 선정      ← 여기서 '사용' 여부와 순위 기록
                 ↓
            생성 프롬프트에 삽입
```

| 열 | 뜻 | 기록 시점 |
|---|---|---|
| 벡터 | 벡터 검색에서의 유사도. 그래프로만 찾았으면 `-` | 벡터 검색 직후 |
| 그래프 | 그래프 탐색에서도 나왔는지 (○ = 두 경로가 같은 청크를 가리킴) | 그래프 탐색 직후 |
| 순위 | RRF 병합 + 리랭킹 후 순위 | 리랭킹 직후 |
| 사용 | 상위 5건에 들어 **프롬프트에 실제로 들어갔는지** | 프롬프트 조립 시 |

**'사용'의 의미를 좁게 잡아야 합니다.** 이 값은 "모델에게 이 문장을 줬다"는 뜻이지, "모델이 이 문장을 근거로 답했다"는 뜻이 아닙니다. 후자를 알려면 답변과 청크를 대조하는 LLM 판정이 필요한데, 그건 자동 평가에 해당하므로 이번 범위에서 제외했습니다(IMP-08).

## 4. 남는 위험

| 위험 | 대응 |
|---|---|
| 파싱에 실패한 표는 경로가 `별표Ⅱ > 업종`까지만 나옴 | 150개 중 1개 수준. 실패 목록을 빌드 리포트에 남기고 화면에서도 얕은 경로로 표시 |
| 표의 비고를 모든 행에 붙이면 임베딩 텍스트가 길어짐 | 비고는 600자로 잘라서 사용. 화면에는 표 단위로 따로 표시 |
| 짧은 해결기준끼리 벡터가 비슷해짐 | 경로를 임베딩 텍스트에 포함(위 §2) |
| 캐시된 입력 토큰을 무시하면 비용이 과대 계산됨 | `cache_read`를 분리해 계산 |
| 장문 조문(1,264자)은 검색 단위가 큼 | 필요하면 호 단위로 한 번 더 쪼갤 수 있음. 지금은 그대로 둠 |
