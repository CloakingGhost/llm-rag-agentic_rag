# 문제 정의서: 소비자 분쟁 Q&A 챗봇 (Agentic RAG 논문 재현 제품)

- 작성일: 2026-09-19 (같은 날 개정 1: 화자 입장, 모델, 로그, 지식베이스 비용 확정 / 개정 2: 그래프 G1, 로그 관리자 전용 / 개정 3: 표 파싱 C, **1차 종료** / 개정 4 (2차 진행 중): 자동 평가 제외, CSV는 제품 밖 수동 테스트 자료로 축소)
- 방법: 실사용자(나) 인터뷰, 5단계 (사용자 정의 → 병목 파악 → 대상 선정 → 수동/자동 경계 → 핵심 KPI)
- 관련 문서
  - [inferred_prompts.md](inferred_prompts.md): 논문 파이프라인 프롬프트 역추론
  - [kb_build_proposal.md](kb_build_proposal.md): 별표 표 파싱(C 결정)과 그래프 구축(G1 결정)
  - [improvement_actions.md](improvement_actions.md): 논문대로 먼저 진행하고 나중에 검토할 개선 조치 항목

## 문제 정의 (한 문단)

분쟁을 겪은 직후의 일반인 소비자는 **자기 상황에 어떤 규정이 적용되는지 스스로 찾지 못한다.** ChatGPT 같은 범용 LLM에 물으면 **근거 없이 답하거나 조문을 잘못 인용한다.** 논문은 사업자의 CS 챗봇에 Agentic RAG(의도 라우터 + 하이브리드 검색 + Self-RAG Critic)를 적용하면 이 문제가 줄어든다고 주장한다. 이 프로젝트는 논문의 3개 파이프라인(Vanilla / Native RAG / Agentic RAG)을 **재현하는 것을 전제로**, 그 차이를 **일반 사용자가 직접 써 보고 눈으로 확인할 수 있는 공개 웹·모바일 제품**으로 만든다.

|---|---|---|
| `ref/논문.docx` | Agentic RAG 파이프라인 구축과 3계층 평가(L1 RAGAS / L2 DSPy / L3 무참조) | 챗봇은 B2C 쇼핑몰 CS(사업자 측). 최종 평가에서 도구 호출·가상 고객 DB는 제외함(4.1절) |

| `ref/별표-소비자분쟁해결기준(…).pdf` | 별표 Ⅰ 대상품목(2~7쪽), Ⅱ 품목별 해결기준(8~141쪽), Ⅲ 품질보증·부품보유기간(142~144쪽), Ⅳ 내용연수표(145쪽) | **145쪽, 표 177개**, 텍스트 PDF. 별표 Ⅱ는 행 구분선이 없음 ([kb_build_proposal.md §1](kb_build_proposal.md)) |
| `ref/전자상거래법(…).doc` | 제1~46조 전문 (2026.7.21 시행, RTF 형식) | 정상 |
| `ref/한국소비자원_…표준답변_20250725.csv` | 1,332건, 56개 품목. 컬럼: 번호/품목명/구분/질문/답변 | 아래 참조 |
| Notion 「논문」 하위 페이지 | 구현 문서, 테스트 결과(5건), PDF 청킹 문제, 평가 계획 | 아래 참조 |

**CSV 표준답변**
- 답변의 48.1%가 소비자분쟁해결기준을, 25.5%가 전자상거래법을 인용함
- **27.6%는 두 지식원 어느 쪽도 인용하지 않음** (민법 170건, 방문판매법 131건, 약관규제법 97건, 표시광고법 66건 등)
- 기준 시점이 다름: CSV 2025.7 / 분쟁해결기준 2025.12 / 전자상거래법 2026.7
- 질문 평균 105자, 답변 평균 515자. 중복 질문 68건, 중복 답변 324건

**이전 구현(Notion)에서 발견한 문제**
- **표 파싱 붕괴**: 별표 Ⅱ의 표가 열 단위로 섞여 추출됨. Native RAG가 이 청크를 읽고 '허위·과장광고' 기준을 잘못 적용함(테스트 케이스 1)
- **그래프 검색 미작동**: 모든 질의에서 그래프가 청크 0~4번(개정 이력·부칙)만 반환함
- **가상 DB 환각**: Agentic이 질문에 없던 "주문하신 무선 청소기"를 언급함(테스트 케이스 3)
- **도구 편향**: 파손 신고에 "결제가 성공적으로 취소되었습니다"라고 실행 결과를 단정함(테스트 케이스 5)

## 1. 사용자 정의

### 1-1. 사용자 계층과 챗봇 화자

| 구분 | 누구 | 목적 | 특성 |
|---|---|---|---|
| **운영자** | 나 (연구자/학생) | 논문을 재현하고 제품으로 공개 | RAG 구현 경험 있음, LangGraph 에이전트는 처음. 평가할 때는 일반인 소비자 입장에서 직접 써 봄 |
| **최종 사용자** | 일반 사용자 (분쟁 직후의 소비자) | 내 상황에서 무엇을 요구할 수 있는지 알기 | 법률 지식은 일반인 수준. 웹·모바일로 접속 |
| **챗봇 화자** | **사업자(쇼핑몰 CS 상담원)** | 소비자 문의에 규정에 근거해 응대 | 논문 설정과 같음 |

### 1-2. 최종 사용자가 답변에서 원하는 것 (우선순위순)

1. **가능/불가 판단**: 내 요청이 되는가
2. **대안**: 안 된다면 무엇을 할 수 있는가
3. **행동 방법**: 누구에게 어떻게 요구하는가
4. **근거**: 법령·원문 자체가 궁금한 것은 아님. **답을 믿을 수 있게 해 주는 장치**로 필요함

### 1-3. 사용 모드

| 모드 | 용도 | 화면 |
|---|---|---|
| `전체 파이프라인 보기` | 논문 실증 | 질문 1회 → 3개 파이프라인 병렬 실행 → **끝나는 순서대로** 한 화면에 표시 |
| `vanilla` / `RAG` / `Agentic` | 평소에 쓰는 제품 | 파이프라인 하나를 고른 단일 챗봇 |
| 대시보드 | 수치 비교 | 파이프라인별 운영 수치 |
| 로그 | 응답 확인 | 저장된 질문 원문, 답변, 처리 과정. **관리자 로그인(`admin`/`admin`) 후에만 보임** |

## 3. 대상 선정 (범위)

### 범위에 포함

| 항목 | 결정 |
|---|---|
| 파이프라인 | Vanilla / Native RAG / Agentic RAG (논문 최종 구성: Intent Router + Vector·Graph 하이브리드(RRF + LLM Re-rank) + Self-RAG Critic) |
| 별표 표 파싱 | **C 규칙 + LLM 보정**: 좌표 규칙 파싱 → 자동 검증 → 실패한 표만 LLM 보정 → 재검증 |
| 그래프 | **G1 논문 방식**: 지식베이스 전체 청크에서 LLM이 개념·관계를 추출 → NetworkX + Louvain |
| LLM | **`gpt-4o-mini` 하나.** 생성·라우터·Critic·리랭커·개념 추출 모든 노드에 사용. 모델 선택 기능은 두지 않음 |
| 임베딩 | `text-embedding-3-large` (논문 기준) |
| 지식베이스 | 전자상거래법 + 소비자분쟁해결기준 본문·별표 Ⅰ~Ⅳ (논문 그대로) |
| 테스트 데이터 | CSV 표준답변은 **제품에 넣지 않음.** 운영자가 CSV에서 질문을 복사해 입력하고, 챗봇 답변과 CSV 답변을 직접 비교하는 수동 테스트 자료로만 씀 |
| 대화 | **싱글턴**. 멀티턴으로 교체할 수 있게 인터페이스를 분리함 |
| 요청 로그 | **질문 원문**, 답변, 경로, 처리 과정, 지연, 토큰을 DB에 저장하고 화면에 로그로 표시 |
| 필수 기능 | ① 파이프라인 1개 선택 대화 ② 1회 요청 → 3개 병렬 → 한 화면 ③ 수치 비교 대시보드 |
| 접속 환경 | 웹 + 모바일(반응형), 공개 URL |

### 범위에서 제외

| 항목 | 이유 |
|---|---|
| 도구 호출, 가상 고객 DB, Context Injector, `system_action` 경로 | 논문 최종 평가에서 제외됨. 이전 구현에서 환각과 도구 편향의 원인이었음 |
| 모델 선택, GPT-4o·GPT-5.6 계열 | `gpt-4o-mini` 하나로 확정 |
| 추가 법령 (민법·방문판매법 등) | 논문 그대로 재현 |
| 사용자 피드백 수집 | 이번 범위 밖 |
| 자동 평가 (LLM-as-a-Judge, RAGAS, DSPy, 무참조 L3) | 채점 비용과 지연이 사용자 키로 청구됨. 오프라인 평가는 IMP-08 |
| CSV 일괄 실행 | 로그는 실제 사용자 입력만 쌓음. 일괄 실행은 IMP-09 |
| 권한·계층 분리 | 구현 난이도를 낮추려고 전부 공개함. 나중에 추가 |
| 멀티턴, 장기 기억 | 싱글턴 먼저. 교체 가능한 구조만 확보 |

## 5. 핵심 KPI

### North Star

> **논문 재현을 전제로, 일반 사용자가 제품 화면에서 3개 파이프라인의 차이를 직접 확인할 수 있다.**

### 5-1. 재현 게이트 (전제 조건)

아래 항목이 동작해야 KPI 측정에 의미가 있습니다.

- 3개 파이프라인이 논문 최종 구성대로 동작함 ([inferred_prompts.md §4](inferred_prompts.md)의 재현 기본값)
- Agentic이 도메인 밖 질문을 거절함 (논문 8.1절: 맛집 질문 → 거절)
- 그래프 검색이 지식베이스 전체를 대상으로 동작함 (질의마다 다른 청크를 반환)

> **참고 (4o-mini 단일 모델의 영향)**: 논문 Table 1에서 가장 약한 모델(GPT-4o)의 L2 순서는 Vanilla 0.636 > Native 0.595 > Agentic 0.525입니다(논문이 '인지 부하 역설'이라고 부른 현상). Notion 테스트(4o-mini, 5건)도 Vanilla 0.76 > Agentic 0.72 > Native 0.47이었습니다. 따라서 이 제품에서 **Agentic의 답이 Vanilla보다 좋아 보이지 않을 수 있고, 그것도 논문과 일치하는 결과**입니다. 개정 4 이후 품질 점수는 측정하지 않습니다. 대신 도메인 밖 거절, 토큰 절감, 지연, 폴백률처럼 **로그만으로 확인되는 논문 주장**은 대시보드로 확인합니다.

### 5-2. 운영 KPI (대시보드)

| 지표 | 단위 | 목표 | 논문 비교 기준 |
|---|---|---|---|
| 지연시간 | 파이프라인별 p50/p95, 노드별 소요 시간 | **목표값 없음, 측정만** | 논문 허용치 15초 |
| 토큰·비용 | 요청당 입력/출력 토큰, 달러 비용 | 측정 | Agentic이 Native 대비 약 42% 절감 (부록 B: 5,873 vs 10,091 토큰) |
| 경로 분포 | 도메인 밖 거절률, Native 폴백률, Native의 '정보 없음' 응답률 | 측정 | — |

### 5-3. 품질 KPI

| 오프라인 평가 (선택) | 저장된 로그로 나중에 L1~L3 채점 (IMP-08) |
