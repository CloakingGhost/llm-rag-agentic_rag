- 1차: 문제 정의
    
	```
	논문을 기반으로  챗봇을 만들거야. @ref 폴더에 있는 자료를 먼저 파악한 후에 
	1차로 문제 정의가 필요하다. 진행 순서는 다음과 같다.
	프로세스 순서: 사용자 정의 → 병목 파악 → 대상 선정 → 수동/자동 경계 → 핵심 KPI
	이 시스템의 실 사용자는 **나**다. 나를 먼저 인터뷰하여 문제 정의가 완료되도록 해줘.
	```
    
- 2차: 업무/데이터 분석
    
	```
	이제 다음 프로세스인 `2차: 업무/데이터 분석`이다.
	
	프로세스 순서: 업무 흐름 정의 → 데이터 정의 → 상태 정의
	
	정의를 위한 인터뷰 시작해줘.
	```
    
- 3차: UX/IA(정보 구조)설계
    
	```
	3차로 UX/IA(정보 구조)설계 단계를 진행하고자 한다.
	프로세스 순서: 정보 구조 설계 → 화면별 핵심 목표 설정 → 상태별 화면 설계
	
	인터뷰 진행해줘.
	```
    
- 4차: 시스템 구조 설계와 기능 명세
    
	```
	4차 진행은 `시스템 구조 설계와 기능 명세`이다.
	프로세스 단계 : 구조 설계 → API 명세 → 배치 작업 명세 → I/F 명세 → 안정성 대비(사용자/권한 관리, API 변경, 인증 만료, 데이터 오류, 중복 실행, rate limit, 실행 실패)
	
	인터뷰 진행해줘.
	```
    
- 5차: UI 디자인
    
	```
	5차 프로세스는 UI 디자인이다. 실제 프로젝트 구성을 진행해서 현재까지의 결정사항들을 모두 문서화하고 시작할 수 있도록 해줘.
	
	프로세스 순서: 프레임 목업 → UI 의사결정 → 테마 선택 → 심화 훈련
	
	이번 프로세스부터는 실제 구현이 시작되는 단계로, 단순 인터뷰가 아닌 **검수 요청 ↔ 피드백 전달 및 수정을 반복**하는 방식으로 진행하겠다.
	
	프론트엔드에 다음 기술 사용: TailwindCSS, shadcn/ui 기본 테마사용하여 프레임 목업 단계부터 시작하자.
	
	완료된 프레임 목업은 실제 환경에서 볼 수 있도록 해줘.
	```

- 6차: 구축 및 검수
    
	```
	이제 6차 프로세스: 구축 및 검수로 넘어갈거야.
	
	프로세스 순서: MVP 구축 → 검수 및 안정화 → 배포(CI/CD) → 추가 구축
	
	MVP 구축을 할 때 목업의 하드코딩되어 있는 경로, 변수로 전화되어야 하는 값, 환경변수로 관리해야 하는 값을 확인하여 배포했을 때 에러가 없도록 해야 돼.
	```
